# GitHub Publishing Steps

## Recommended repository name

`manufacturing-erp-storage-sync-case-study`

Alternative:

`enterprise-manufacturing-integration`

Avoid using an employer's name in the repository title unless you have explicit permission.

## 1. Create the repository

On GitHub:

1. Click **New repository**.
2. Choose the repository name.
3. Set visibility to **Public** only if all uploaded material has been sanitized and you are allowed to discuss the project.
4. Do not upload production code, credentials, internal logs, or confidential screenshots.
5. Create the repository.

## 2. Upload this showcase package

Upload:

- `README.md`
- `SECURITY.md`
- `.gitignore`
- `docs/`
- `src-sample/`

## 3. Recommended repository description

> Sanitized case study of a C#/.NET real-time integration engine connecting manufacturing ERP receiving data with an automated storage workflow.

## 4. Suggested GitHub topics

`csharp` `dotnet` `sql-server` `winforms` `system-integration` `manufacturing` `automation` `enterprise-software` `industrial-automation`

## 5. Add portfolio link

After publishing, add the repository to:

- LinkedIn Featured section;
- LinkedIn Projects;
- personal portfolio;
- resume project/achievement section where appropriate.

## 6. Before making it public

Confirm all of the following:

- [ ] No credentials
- [ ] No production connection strings
- [ ] No server/IP names
- [ ] No private company data
- [ ] No customer information
- [ ] No proprietary screenshots
- [ ] No employer-owned source code without permission
- [ ] No confidential metrics
- [ ] Repository accurately describes your own contribution

## 7. Keep EB-1A evidence separate

Your private EB-1A evidence package can contain authorized internal documentation, signed declarations, production metrics, logs, and corroborating exhibits.

Do **not** make the immigration evidence folder itself public on GitHub.
